# 构件、管线、零件的碰撞点位标注与文字说明

本模块用于实体干涉、构件相交、管线冲突、要求净距不足，以及用户已给出点位的编号标注。尺寸文字或引线之间的排版重叠不属于物理碰撞，但新增标注本身需要保持清晰可读。

## 1. 选择范围与交付方式

- 用户提供坐标、对象句柄、问题清单或截图标记：优先登记这些点，不擅自扫描整图。保留用户提供的描述，区分“用户提供”与“几何已验证”。
- 用户明确要求查找碰撞：按其指定构件、系统、图层、楼层、区域或对象集合检查。没有范围时使用当前明确选定的对象或可见区域，并说明覆盖范围；未检查的对象不计入“无碰撞”。
- “标注点位并说明”包含创建可见审查标记和引线的授权。明确要求仅检查、列清单或不改 DWG 时，只生成文字报告和外部截图叠加标记。不要重复索取已经给出的普通标注授权。
- 单位、WCS/UCS、布局、楼层/标高、净距阈值和适用规范影响判定时，应优先从图纸及项目要求读取。缺少规定净距时可以报告实测间距，但不能自行假定一个最小值并判定不合格。
- 修改原构件来消除碰撞、覆盖保存 DWG、关闭图纸或调用破坏性命令，需要对应的用户请求；创建审查标注不包含这些行为。

## 2. 获取证据并判断问题

先执行主技能的运行环境预检、图纸信息读取、实体扫描与 CAD-IR 构建。保留当前图纸标识、扫描时间/快照、对象句柄、类型、所属构件/系统、图层和单位。

### 候选与确认

1. 根据用户点位、语义对象、验证报告和包围盒筛选相关对象。包围盒只用于筛选，不能直接作为实体干涉结论。
2. 用 `explain_entity`、`get_entity_properties`、`get_entity_topology` 或 `get_bounding_box` 获取现有 MCP 实际支持的几何与属性。块、外部参照和管线组须核对成员范围及变换；不要把内部子对象互相接触计作多个独立构件冲突。
3. 二维曲线交点可由 `intersect_with` 核验，但必须选择运行时实际对应 `acExtendNone` 的不延伸选项，并检查交点落在原始有限几何上。不要为了找到交点延伸线段。封闭轮廓完全包含、重复重合和实体内部交叠还需要区域/实体证据，不能靠“没有边界交点”排除。
4. 三维实体优先使用经验证能正确解码返回值的 `check_interference`。显式 `create_solid=False`，避免该工具默认创建干涉体。区分检测失败、未覆盖、接触与已确认干涉。
5. 净距问题必须记录测量对象的实际外表面、测量方法、实际值、规定值和单位。轴线距离不是表面净距；管线需考虑半径/外径、保温层及标高，缺失这些数据时保持 `unknown`。没有经过验证的距离工具或完整可计算几何时，报告测量能力缺口。
6. 截图/VLM 只负责提出候选。用 `export_view_image_with_mapping`、`ground_vlm_region`、`ground_vlm_overlay_id` 和对象解释建立关联；没有可靠深度或坐标映射时只能描述“投影交叉/待核实区域”。二维投影交叉不能证明真实三维碰撞。

### 工具返回值核对

不要发明 `detect_collisions`、`annotate_collision` 等工具。先核对当前连接实际公开的工具、参数、适用实体类型和返回结构；缺少能力时交付已完成的报告并列出未完成的检测/标注项。

Autodesk 的 [CheckInterference 接口](https://help.autodesk.com/cloudhelp/2024/CHS/AutoCAD-LT-ActiveX-Reference/files/GUID-D22E6F22-B774-48B1-8A85-01F81F1C80E4.htm)把干涉布尔值定义为 `SolidsInterfere` 输出参数，返回的实体取决于是否创建干涉体。核对 MCP 包装层是否解码该输出：不能只对返回对象/元组做 `bool(result)`，也不能用 `create_solid=False` 时未返回实体证明“无干涉”。解码无法验证时，结果为 `unknown`，不得通过创建实体来偷偷绕过只读要求。

[IntersectWith 接口](https://help.autodesk.com/cloudhelp/2026/JPN/AutoCAD-ActiveX-Reference/files/GUID-1243A593-5DAE-4DC3-B539-59FDA990E687.htm)区分不延伸、延伸单方及延伸双方。核对包装层对 `AcExtendOption` 的真实传递，避免依赖可能与运行时不一致的参数说明。

`validate_geometry` 的成功状态不是完整的物理碰撞检测结论。确认实际检查项、对象范围和返回问题；保留截断扫描、不可访问 Xref 和不支持的曲面/网格等覆盖缺口。

## 3. 点位记录、编号与描述

同一对构件在同一几何区域产生的重复发现可以合并；不同楼层、不同系统或相隔明显的碰撞区域分别记录。按对象身份与位置稳定编号 `CL-001`、`CL-002`，重复检查复用既有 ID，不能按工具返回顺序不停换号。

每个点位记录以下内容；未知项使用 `null` 和原因，不填虚构数字：

| 字段 | 要求 |
|---|---|
| `id` / `drawing_ref` | 唯一编号；实际图纸/布局/快照标识 |
| `kind` | `hard_interference`、`clearance_shortfall` 或 `supplied_location` |
| `status` | `confirmed`、`candidate`、`user_supplied`、`unknown`、`resolved`；仅复查通过才能设 resolved |
| `objects` | 实体句柄、构件/管线名称、图层/系统；没有可靠句柄时明确记缺口 |
| `location` | 实测 WCS `[x,y,z]`、单位、原输入坐标系、测量依据；未知 Z 保留 null，不假设为 0 |
| `location_quality` | `measured_point`、`user_point`、`approximate_region` 或 `unlocated` |
| `region` | 碰撞区域或审查范围；记录二维投影、三维 bbox 或截图 bbox 的类型及坐标系 |
| `measurement` | 实际净距/干涉量（若可获得）、要求值、单位、方法和阈值来源 |
| `description` | 涉及什么对象、在哪里、发生什么问题、依据是什么；默认使用用户语言 |
| `impact` / `recommendation` | 对安装/通行/维护/装配的可能影响与建议；没有依据不声称必然失败、不编造调整量 |
| `evidence` / `uncertainties` | 工具结果、句柄、视图/截图索引、置信依据及待核实项 |
| `annotation` | `pending`、`dwg_verified`、`overlay_only`、`failed` 或 `skipped`，新增标记/引线句柄、输出文件 |

真实干涉通常是一个区域，不一定存在唯一“碰撞点”。优先使用可靠的交点或已测量区域代表点；用包围盒交集中心作为显示锚点时必须写“近似审查区域”，不能把它称为实测碰撞坐标。干涉已确认但位置未知时，分别记录两种状态，不强行画精确点。

文字说明格式：

> CL-编号｜状态｜对象 A 与对象 B｜位置及单位｜问题及测量依据｜可能影响｜建议｜待核实项。

净距项明确写“实测净距”“要求净距”及差值，只有可靠测量和规定值都存在时才计算差值。图上使用短描述，完整说明放入报告；不要用仅有“这里碰撞”的标签代替逐点描述。

## 4. 创建可见标注

标记是用户可见的审查交付物；内部推理、候选管理和句柄映射仍存外部报告或 SQLite，不写入隐藏 DWG 图层/XData。

- 优先项目现有的审查图层和样式。没有规定时，创建 `CAD-CLASH-MARK` 与 `CAD-CLASH-TEXT`；不要覆盖同名图层的已有样式。图示约定可用红色表示已确认问题、黄色表示候选/待核实，并在文字中写明状态，不只靠颜色。
- 点标记/圆圈与引线首端绑定到同一个记录位置；引线末端放在图形外围，避免盖住已有尺寸、BOM、构件轮廓和其他点位。文字尺寸采用当前注释比例；无标准时按图纸纸面字高约 2.5–3.5 mm 制定并记录，不把它直接当作模型单位。
- 平面 WCS Z=0 可用 `draw_circle` 圈出点位并用 `add_mleader(text, points, layer)` 写编号和短描述。`draw_circle` 的现有签名没有 Z 参数，不能用它标记任意三维坐标；三维点优先用实际支持的 `draw_point(x,y,z,...)` 和三维引线，圆圈若是投影标记必须说明投影视图。
- 对有效区域但没有精确点的记录，采用区域圈注或导出截图的区域框，注明“近似区域/待定位”；没有可靠映射时不在 DWG 中编造坐标。
- 可由 `draw_circle`、`add_mleader`、`create_layer` 等已绑定操作构成的批量标注先生成 CADPlan，validate → dry-run → 在用户已授权范围执行。`draw_point` 或其他尚未绑定的操作使用真实直接 MCP 工具逐项执行，记录结果；不能把不支持的操作写进计划后宣称它已验证或事务回滚有保证。
- 保存新增标记/引线的实际句柄，恢复工具改变的当前图层等会话设置。追加文字不能移动或改色原构件。
- 重复运行根据同一图纸、ID 和已保存句柄核对既有标注，避免重复创建。不能删除原标注或旧问题记录来掩盖结果；删除/清理按用户请求和实际归属处理。

只做报告或截图时，输出外部图片叠加编号、点/区域、引线和说明。没有 live MCP 时仍可整理用户点位与文字；明确记录 `overlay_only` 或 `pending`，不宣称已在 DWG 标注。

## 5. 复查与输出

1. 执行后重新扫描，查询每个新增句柄的实体类型、图层、内容和位置。标记中心/引线端点与记录位置的误差须在项目要求或所声明的测量精度内；无精度依据时不要硬称毫米级。
2. 输出全局定位视图及每处问题的局部视图，复查中文字体、编号、颜色、字高、引线归属、遮挡和输出纸面的可读性。只验证文本存在不能证明点位正确。
3. 对比原对象句柄、几何与已有尺寸/BOM，确认仅增加获准的审查标注。标注成功不是碰撞已消除；只标注时保持问题状态。
4. 在用户指定输出目录生成 `collision-report.md` 与 `collision-points.json`；未指定时用当前 CAD 工作区的 `collision-review/`。两者 ID 与图上 ID 一一对应。
5. 报告列出检查范围、单位/坐标系、判据来源、确认/候选/未知数量、逐点表、局部图索引和能力缺口。JSON 存上述结构化记录及检测/标注状态，便于后续改文字、改点位和复查。
6. 根据用户要求及可用工具导出带标注 PNG/PDF；DWG 保存仅在用户请求后执行。任何工具失败都保留已完成项及其句柄，不把部分完成说成全部完成。

## 6. 调整与触发

后续修改主要在本参考文件中进行：检查范围、点位字段、编号前缀、图层命名、颜色、文字格式、注释比例和报告要求。具体项目的对象集合及净距阈值在执行时读取，不硬编码到通用技能里。

触发示例：

- “把这些管线碰撞点编号，并用引线逐点说明。”
- “检查 A 系统与 B 系统的干涉和净距不足，标注已确认的问题。”
- “将这份零件干涉清单的坐标标到装配图上，生成问题描述。”
- “只输出碰撞点位与文字报告，不改原 DWG。”

这些是流程指令扩展，不是新安装的碰撞求解器。实际检测和 DWG 标注依赖可用且已验证的 best-cad-mcp 工具、AutoCAD 连接及输入几何。
